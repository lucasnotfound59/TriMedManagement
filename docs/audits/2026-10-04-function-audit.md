## 已确认的问题

### A01 · P1 · 慢网下第二次保存会丢失

- 页面：`/me/edit`；共同存储逻辑也用于其他患者记录。
- 复现：使用本次新注册的虚构账号，把 `/api/data` 的 PUT 延迟 2.6 秒；修改家族史并保存；第一笔 PUT 尚未完成时，再修改过敏史并保存；等待请求完成后刷新。
- 实际：第二次修改已显示在档案中，但只发出 **1 次 PUT**。服务器保存了第一项修改，过敏史仍为空；刷新后第二项修改消失。
- 原因：`src/lib/store.tsx:226` 在 `pushing` 时直接返回。第二次修改的 800 ms 同步定时器触发时，第一笔请求仍在进行；定时器已清除，第一笔完成后也没有继续推送新状态。资料页 `src/app/me/edit/page.tsx:49` 起的保存流程在服务器确认前显示“已保存”。
- 应有行为：保留尚未提交的修改，并在当前请求结束后继续保存；界面应区分保存中、保存成功和失败。
- 证据：[请求与刷新结果](assets/slow-save.json)、[刷新前的第二次修改](assets/slow-save-before.png)。

### A02 · P1 · 未填写病史被写成“无”，并展示给医生

- 页面：`/doctor/[id]`；`/doctor/year` 共用同一报告组件。
- 复现：注册时把基础病和过敏史留空；在 `/visit` 输入虚构的不适描述；点击“整理成给医生看的一页”。
- 实际：服务器档案为 `conditions: []`、`allergies: []`，但报告第一屏写成“既往：无特殊”“过敏：无已知过敏”。英文也显示 `History: nothing notable`、`Allergies: none known`。
- 原因：`src/components/DoctorSheet.tsx:104` 和 `:143` 把空数组当成已确认的阴性病史。该区域属于打印报告的内容，不能把缺失信息转换为患者未说过的结论。
- 应有行为：空白显示“未记录 / Not recorded”；患者明确说“无”时，才按原话展示。
- 证据：[未填写信息的医生报告](assets/empty-history.png)。

### A03 · P2 · 手机端问答页快捷问题被输入栏遮住，无法点击

- 页面：`/ask`；复现尺寸：390 × 844。
- 复现：打开林叔演示 → 问医伴 → 点击“上次医生说了什么？” → 滚到最底部 → 点击“我有哪些老毛病和在吃的药？”。
- 实际：按钮存在，但点击中心命中固定的输入框；正常浏览器点击持续被拦截。滚到最底部仍无法把该按钮移出遮挡区。
- 原因：`src/app/ask/page.tsx:55` 计算底部留白时只计入输入栏高度，未计入其 `bottom: var(--tab-bar)` 偏移。输入栏和底部导航占据的总高度大于页面留出的空间。
- 证据：按钮矩形 y=604.31～655.31，中心命中的元素为 `textarea[aria-label="问医伴"]`；[手机截图](assets/ask-blocked.png)、[命中结果](assets/ask-blocked.json)。

### A04 · P2 · AI 状态把 Claude 与 GLM 语音能力混在一起

- 页面：`/me/settings`、`/pre` 及其他使用语音可用性开关的页面。
- 复现配置：选用 Claude，提供非真实的占位配置，GLM 语音密钥留空。未向模型供应商发起请求。
- 实际：`GET /api/health` 返回 `configured: true`、Claude 模型名；设置页却显示“已连接智谱 GLM”，并列出语音模型。语音按钮显示可用，而 `POST /api/transcribe` 实际返回 **503**：“语音识别需要先配置 AI”。
- 原因：`src/app/api/health/route.ts:9` 只返回聊天供应商的配置状态；`src/components/AiStatus.tsx:38` 用该状态同时决定语音可用性；`src/app/me/settings/page.tsx:282` 硬编码了 GLM 文案。实际语音依赖 `src/lib/ai/glm.ts:225` 的独立 GLM 配置。
- 应有行为：分别报告供应商、聊天/照片/语音能力，并区分“已配置”和“连接测试成功”。
- 证据：[Claude 配置下的连接提示](assets/claude-status.png)。

### A05 · P2 · 数据存储说明与实际实现不符

- 页面：`/me/settings` → 我的数据 → 数据存在哪里。
- 实际：中文和英文都声称档案“只存在这台设备的浏览器里”。本次注册账号的数据实际通过 `/api/data` 保存到服务端 SQLite，浏览器只保留会话标记和语言设置；本地演示账号才把虚构数据放在 localStorage。
- 位置：`src/app/me/settings/page.tsx:221`；实际存储分流见 `src/lib/store.tsx:160`、`:205` 和 `src/lib/server/secure-db.ts`。
- 应有行为：按真实账号与演示账号说明各自存储位置，保持与 README 的服务端存储说明一致。
